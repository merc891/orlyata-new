# ТЗ: публичный вывод CMS-контента

Статус: рабочая спецификация.  
Назначение: зафиксировать правила выборки, сортировки, даты и обязательности данных до подключения production-шаблонов к CMS.

Этот документ дополняет `docs/project.md`, `docs/architecture.md` и `docs/cms-schema.md`. Если он меняет модель данных или SEO-правила, соответствующие документы и код `orlyata-core` синхронизируются отдельной задачей до реализации.

## 1. Общий контракт публичных списков

### 1.1. Публичность и предпросмотр

- Публичный сайт выбирает только записи WordPress со статусом `publish`.
- Запланированные публикации не используются.
- Черновики, pending, private, trash и любые иные статусы не попадают в публичные запросы.
- Редактор может использовать штатный авторизованный preview WordPress для неопубликованной записи. Такой preview не является публичной страницей, не попадает в sitemap и не должен кэшироваться как публичный контент.

### 1.2. Даты, время и стабильная сортировка

- Для `news` пользователю выводится дата публикации WordPress (`post_date`).
- Для `photo_album` и `video` пользователю выводится дата добавления — `post_date` записи в WordPress.
- Во всех списках, где принята сортировка «сначала новые», используется полная дата и время `post_date DESC`, а не только календарная дата.
- При полностью совпадающем `post_date` вторичным ключом служит `ID DESC`; порядок записей остаётся стабильным между запросами и страницами пагинации.
- Обычное редактирование не меняет положение материала в выдаче: `post_modified` не участвует в сортировке.

### 1.3. Отображение даты для новостей и медиагалереи

Правило применяется к карточкам и спискам `news`, `photo_album` и `video`; расчёт ведётся в часовой зоне сайта WordPress.

| Возраст публикации | Видимый формат | Пример |
| --- | --- | --- |
| Сегодня | `Сегодня, HH:MM` | `Сегодня, 17:54` |
| Вчера | `Вчера, HH:MM` | `Вчера, 23:20` |
| Позавчера и ранее, текущий год | `D MMMM` | `23 мая` |
| Прошлый календарный год | `D MMMM YYYY` | `23 декабря 2025` |

- Время выводится в 24-часовом формате с ведущим нулём.
- Для текущего года год не выводится.
- Относительные слова «Сегодня» и «Вчера» определяются по локальной календарной дате сайта, а не по разнице в 24 часа.
- Публичный HTML содержит уже сформированную строку; JavaScript не меняет дату после загрузки.

### 1.4. Закрепление

- Ручного закрепления, признака «избранное» и отдельного приоритета материалов нет.
- Новые материалы не могут быть подняты или опущены в ленте иначе, чем их датой и временем публикации/добавления.

## 2. Контентная валидация и медиа

### 2.1. Длина заголовка

- Для `news`, `photo_album` и `video` заголовок обязателен и ограничен 100 символами, включая пробелы.
- Ограничение проверяется серверно при сохранении. Счётчик в редакторе может помогать пользователю, но не заменяет серверную проверку.
- Под «символом» понимается один Unicode-символ, а не байт; русские буквы учитываются корректно.

### 2.2. Новости без анонса

- У `news` нет отдельного поля анонса, краткого описания или автоматически сформированного excerpt.
- В списках и на главной выводятся только утверждённые данные: название, дата и категория с иконкой.
- Детальная страница выводит название, дату, категорию и детальный текст.

### 2.3. Фотоальбомы

- Фотоальбом должен содержать изображения.
- Редактор выбирает обложку только из изображений этого альбома.
- Если отдельная обложка не выбрана, публичный слой использует первое изображение в заданном редактором порядке.
- Если в опубликованном альбоме нет доступного изображения, он не соответствует контракту и не должен публиковаться без отдельного решения об error/fallback-состоянии.

### 2.4. Видео

- Внешний URL видео остаётся обязательным, нормализуется сервером и разрешается только для поддерживаемых провайдеров.
- Нужна ли обязательная загружаемая обложка-предпросмотр, пока не решено. До решения продолжает действовать текущий fallback, определённый контрактом provider adapter.
- Генерация обложки из внешнего видео — открытый вопрос реализации. На этапе реализации отдельно выбираются сервис и технический способ, после чего должны быть согласованы условия использования, стоимость, передача данных, отказоустойчивость и внешняя зависимость.

## 3. SEO фильтров и поиска

- Принято требование индексировать страницы фильтрации и поиска.
- До реализации нужно утвердить канонические URL, допустимый набор параметров и правила canonical, чтобы не создать бесконечные или дублирующие URL.
- Индексироваться могут только валидные комбинации поддерживаемых параметров. Неизвестные, пустые и некорректные значения не образуют отдельные индексируемые страницы.
- Для каждого индексируемого состояния должны быть определены уникальные `title`, `description`, canonical и правила включения в XML sitemap.

## 4. Карта страниц и решения

### 4.1. Главная `/`

| Блок | Источник | Выборка и порядок | Представление / переход |
| --- | --- | --- | --- |
| Новости | `news` | Ровно 2 опубликованные записи всех трёх категорий (`news`, `announcement`, `achievement`), `post_date DESC`, затем `ID DESC`. | Две NewsCard; каждая ведёт на детальную страницу новости. |
| Медиагалерея | Единая выборка `photo_album` и `video` | Ровно 3 опубликованных материала обоих типов, `post_date DESC`, затем `ID DESC`. Один материал может повторно появляться в профильном разделе медиагалереи; внутри одной выдачи запись не дублируется. | Первая запись всегда выводится вариантом большой MediaCard, вторая и третья — маленьким вариантом, независимо от типа материала. |
| Достижения | `choir_achievement` | Не более 20 опубликованных записей, `post_date DESC`, затем `ID DESC`. | Семантическая таблица. Ссылка «Все достижения» ведёт к якорю `#achievements` на `/o-kapelle/`, поскольку отдельной страницы достижений нет. |
| Педагоги в блоке истории | `teacher` | Выводятся только два конкретных педагога: Андрей Чернецов и Ирина Карпман. Выбор остаётся статичной композицией страницы, а не автоматической выдачей. | Фотографии и имена принадлежат соответствующим CMS-записям; каждая ссылка ведёт на реальную детальную страницу педагога. В коде ссылка получается по записи, а не жёстко заданным URL. |
| Цифры и факты | `site_settings` | Ровно 4 редактируемые позиции в фиксированном порядке. Каждая позиция содержит значение и подпись. | Четыре существующие карточки Advantage. При неполном наборе требуется отдельное решение о fallback до реализации. |

Дополнительные правила главной:

- Новости и медиагалерея используют полную дату и время записи для порядка, а не только видимую календарную дату.
- Сортировка достижений основана на дате публикации записи; поле года достижения является отображаемыми данными строки и не влияет на порядок.
- Блоки на главной не получают ручного закрепления и не используют признак «избранное».

### 4.2. Новости `/novosti/`

| Аспект | Решение |
| --- | --- |
| Источник | `news`, только записи со статусом `publish`. |
| Фильтр | «Все», «Новости», «Объявления», «Достижения». Фильтр «Все» показывает записи всех категорий. Категория, в которой нет опубликованных записей, не выводится как вариант фильтра. |
| URL фильтра | `/novosti/?category=<slug>`, например `/novosti/?category=news`. Допустимы только slug закрытого словаря `orlyata_news_category`. |
| Сортировка | `post_date DESC`, затем `ID DESC`: от более новых материалов к более старым. |
| Объём и навигация | Выводятся все материалы выбранной категории в единой серверной таблице; пагинации, кнопки «Показать ещё» и клиентской подгрузки нет. |
| Состав строки списка | Название, дата по общему правилу форматирования, иконка категории и текстовое название категории. Строка ведёт на детальную страницу новости. |
| Пустое состояние | Для валидной, но пустой категории отдельный пункт фильтра не показывается. Если опубликованных новостей нет вовсе, выводится предусмотренное страницей empty state. |

NewsCard остаётся компонентом preview-блока на главной. Список `/novosti/` использует таблицу и не обязан повторять карточную композицию.

### 4.3. Детальная новость `/novosti/{slug}/`

Страница выводит:

1. название;
2. дату публикации;
3. категорию как текстовый тег с иконкой категории;
4. детальный текст;
5. блок шаринга: ссылки на «ВКонтакте», Telegram и действие «Скопировать URL»;
6. блок «Другие новости» — список из 10 последних опубликованных новостей всех категорий, отсортированный `post_date DESC, ID DESC` и не включающий открытую запись.

Шаринг не изменяет содержимое новости. Ссылки на внешние сервисы должны содержать только URL публичной новости; действие копирования является progressive enhancement и не должно быть единственным способом получить адрес страницы.

### 4.4. Нотная библиотека `/noty/`

| Аспект | Решение |
| --- | --- |
| Источник | `score`, только записи со статусом `publish`. |
| URL поиска и фильтра | `/noty/?q=чичков&choir=junior`. Параметр `q` содержит поисковую строку по названию и автору; `choir` — допустимый slug закрытого словаря хоров. Параметры работают совместно и сохраняются при навигации. |
| Сортировка | По названию произведения: сначала кириллица А–Я, затем латиница A–Z. |
| Объём | На первой выдаче — 50 результатов. |
| Навигация | Если результатов больше 50, отображается «Показать ещё», открывающая следующую серверную страницу результатов с сохранением `q` и `choir`. JavaScript может улучшать это действие подгрузкой, но не является обязательным. |
| Колонки таблицы | Название произведения, автор, хор, файл. |
| Файл | Обязательное поле: PDF или изображение. Файл доступен для скачивания без JavaScript; браузер получает имя файла, под которым он хранится в медиатеке WordPress. |
| Пустое состояние | Текстовое empty state показывается только при ненулевом поисковом запросе, для которого нет результатов. Его точный текст и внешний вид берутся из отдельного макета, который будет предоставлен перед вёрсткой. |

Если фильтр хора без поискового запроса не находит записей, специальный текстовый empty state не выводится до отдельного решения по макету.

### 4.5. «О капелле» `/o-kapelle/`

#### Педагоги

| Аспект | Решение |
| --- | --- |
| Источник | `teacher`, только записи со статусом `publish`. |
| Основной порядок | Обязательное числовое поле «порядок» по возрастанию. |
| Уникальность порядка | Значение «порядок» не может быть пустым и не может повторяться у другого педагога. Серверная валидация не даёт сохранить или опубликовать запись с нарушением этого правила. Вторичная сортировка не требуется. |
| Объём | На странице выводятся первые 6 педагогов. |
| Карточка / ссылка | Карточка ведёт на детальную страницу соответствующего педагога. |
| Детальная страница | Имя, должность, звание — только если оно заполнено, обязательная фотография, цитата — только если она заполнена, все добавленные фотографии педагога без искусственного лимита, таблица личных достижений педагога. |
| Обязательность | Основная фотография обязательна для публикации. Отсутствие цитаты не является ошибкой и не выводит пустой блок. |

#### Достижения капеллы

| Аспект | Решение |
| --- | --- |
| Источник | `choir_achievement`, только записи со статусом `publish`. |
| Сортировка | `post_date DESC`, затем `ID DESC`: от более новых к более старым, как на главной. |
| Объём | Выводятся все строки, без фильтров и пагинации. |
| Представление | Семантическая таблица с теми же колонками, что на главной: год, результат/награда, хор, конкурс или событие. |
| Один год | Одно достижение — одна строка, в том числе когда несколько достижений имеют один год. |
| Пустое состояние | Если опубликованных достижений нет, блок достижений целиком не выводится. |

### 4.6. Медиагалерея `/mediagalereya/`

Страница является навигационной страницей раздела, а не полной смешанной лентой.

| Блок | Источник | Выборка и порядок | Представление / переход |
| --- | --- | --- | --- |
| Общий медиа-блок | Единая выборка `photo_album` и `video` | Ровно 3 опубликованных материала обоих типов, `post_date DESC`, затем `ID DESC`. | Та же композиция, что на главной: первая MediaCard большая, вторая и третья — маленькие. |
| Фото | `photo_album` | До 10 опубликованных альбомов, `post_date DESC`, затем `ID DESC`. | Серверная таблица-preview и ссылка на полный список `/mediagalereya/foto/`. |
| Видео | `video` | До 10 опубликованных записей, `post_date DESC`, затем `ID DESC`. | Серверная таблица-preview и ссылка на полный список `/mediagalereya/video/`. |

- Один материал может одновременно появляться в общем медиа-блоке и в соответствующей таблице-preview.
- Полные правила фильтров, лимитов, пагинации и пустых состояний списков фото и видео принадлежат маршрутам `/mediagalereya/foto/` и `/mediagalereya/video/` и фиксируются отдельно.

- Desktop-композиция галереи следует Figma `4566:4087`: в ряду пять фотографий — одна большая и четыре маленькие. Перед визуальной реализацией этот узел должен быть извлечён через Figma MCP, а решение отражено в дизайн-системе.

### 4.9. Контакты `/kontakty/` и footer

#### Контакты

- Обязательные группы данных: адрес, связь и социальные сети.
- Телефон выводится в формате `+7 (123) 456-78-90`.
- Адрес выводится в формате `г. Зеленоград, Центральная площадь, 1, КЦ "Зеленоград"`.
- Часы работы, карта и реквизиты не выводятся.
- Иконки социальных сетей выводятся в фиксированном порядке: «ВКонтакте», затем Telegram.

#### Footer

- Данные footer не редактируются через CMS и задаются в коде темы.
- Footer не использует `site_settings` и не зависит от заполнения страницы «Контакты».

## 5. Открытые решения

Следующие вопросы не были отвечены и не должны быть неявно решены в коде:

1. Нужна ли для видео обязательная загружаемая обложка; если нет — какой fallback используется при недоступном внешнем видео после публикации?
2. После инвентаризации старого сайта утвердить финальную карту URL и точные 301-редиректы для всех изменённых адресов, включая текущий раздел новостей `https://zelorlyata.ru/about/news/` → `/novosti/`. Нельзя направлять все старые адреса на главную: каждому нужен ближайший релевантный новый URL, 410 или 404.

## 6. Последствия для реализации

- `orlyata-core` должен валидировать длину заголовка и обязательность изображений фотоальбома до перевода записи в `publish`.
- Поле анонса `news` не создаётся и не переносится при миграции; публичные query helpers и шаблоны не формируют excerpt из детального текста.
- Query helpers должны использовать `post_date DESC, ID DESC` в выдачах «сначала новые».
- Нужен общий query helper, который объединяет `photo_album` и `video`, стабильно сортирует их по `post_date DESC, ID DESC` и возвращает первые три записи для главной.
- Общий query helper медиагалереи переиспользует ту же смешанную выборку трёх материалов; отдельные helpers фотоальбомов и видео возвращают по десять строк для preview-таблиц.
- Полные query helpers фото и видео должны фильтровать по закрытой медиа-категории и возвращать все опубликованные материалы в порядке `post_date DESC, ID DESC`; helper фото исключает альбомы без доступных изображений.
- Нужен query helper списка новостей с серверным фильтром категории и helper «Другие новости», исключающий текущую запись.
- Нужен paginated query helper нот с параметрами `q`, `choir` и размером страницы 50; он должен сортировать кириллицу перед латиницей и возвращать серверную ссылку «Показать ещё».
- Поле файла `score` необходимо расширить с PDF до PDF или изображения и валидировать MIME-тип на сервере.
- Поле `teacher` «порядок» становится обязательным и уникальным среди педагогов; его проверка должна выполняться серверно и при сохранении, и перед публикацией.
- Нужны query helpers педагогов (по уникальному ручному порядку, лимит 6) и достижений (полная выдача по `post_date DESC, ID DESC`).
- В `site_settings` потребуется добавить четыре упорядоченные позиции «цифры и факты» (значение и подпись); это не новый тип публичного контента.
- Статичная композиция блока истории должна ссылаться на CMS-записи Андрея Чернецова и Ирины Карпман через разрешение их канонических slug/ID, без жёстко заданных публичных URL.
- Formatter даты должен быть единым серверным helper’ом, а не дублироваться в PHP-шаблонах или JavaScript.
- Добавление ID видеообложки и миграционная стратегия для существующих видео зависят от решения об обязательности обложки.
- Контакты используют утверждённые форматы адреса, телефона и порядка соцсетей; footer должен быть отделён от `site_settings` и содержать статичные значения в теме.
- Правила индексирования параметрических URL требуют отдельного SEO-контракта до настройки sitemap и canonical.

## 7. Нефункциональные требования

1. Основные списки, поиск, фильтры, ссылки и навигация по результатам работают без JavaScript. JavaScript может сделать интерфейс удобнее — например, подгрузить следующую порцию нот без обновления страницы, — но не является обязательным для получения контента. Это progressive enhancement: сайт остаётся доступным при отключённом JavaScript, медленном соединении или ошибке скрипта.
2. Фильтры и поиск сохраняются в URL, включая переход на следующую страницу результатов.
3. Любой текст из CMS выводится как текст, а не как исполняемый HTML или JavaScript; это называется экранированием. Сервер принимает и выводит только разрешённые URL, изображения и внешние видео: проверяет их формат, источник и тип файла до сохранения и повторно безопасно выводит в шаблоне. Это защищает посетителей и редакторов от случайной или вредоносной вставки кода и ссылок.
4. Публичные посетители и любые неавторизованные пользователи не видят черновики, приватные материалы и заявки. Авторизованный редактор может открыть только разрешённый ему авторизованный preview своей неопубликованной записи; заявки не доступны роли `content_editor` и видны только администратору.
5. Изображения используют подходящие размеры WordPress, `srcset`, `sizes`, `width` и `height`, чтобы не загружать оригинал без необходимости и не допускать сдвигов макета при загрузке.
6. Правила объёма запросов следуют утверждённым разделам: новости, фото и видео показывают полные разрешённые списки без пагинации; ноты выводятся порциями по 50; preview-блоки используют свои лимиты 2, 3, 10 или 20 элементов.
7. Для внешнего видео нужен fallback — запасной безопасный вид карточки или страницы, если внешний видеохостинг, preview или сам ролик недоступен. Конкретный вариант fallback остаётся открытым до решения о видеообложке.

## 8. Критерии приёмки принятых решений

- Публичный список не показывает ни одной записи, чей `post_status` отличается от `publish`.
- Две записи с одной календарной датой выводятся по времени добавления; при идентичном времени порядок определяется убывающим ID.
- Материал, опубликованный сегодня или вчера, выводит слово, запятую и время; более старые материалы следуют утверждённому формату даты.
- Заголовок длиннее 100 символов не может быть сохранён как опубликованный у новости, фотоальбома или видео.
- Нельзя опубликовать видео без внешнего URL либо фотоальбом без хотя бы одного изображения.
- Решение об обложке и fallback для недоступного внешнего видеопревью принимается до реализации video provider adapter.
- Главная выводит ровно две опубликованные новости всех категорий и ровно три опубликованных медиаматериала обоих типов в заданных вариантах карточек.
- Главная выводит не более 20 опубликованных достижений, а её ссылка «Все достижения» открывает якорь `#achievements` на странице «О капелле».
- Карточки «Цифры и факты» используют четыре значения из `site_settings`, а ссылки педагогов ведут на детальные страницы соответствующих CMS-записей.
- `/novosti/` выводит полную серверную таблицу опубликованных новостей выбранной категории без пагинации; пустая категория не появляется в фильтре.
- Детальная новость выводит заданные поля, блок шаринга и ровно до 10 последних других опубликованных новостей без текущей записи.
- `/noty/` сортирует результаты по названию (А–Я, затем A–Z), выводит первые 50 и позволяет получить следующий набор без JavaScript с сохранением активных поиска и фильтра.
- Ноту нельзя опубликовать без файла PDF или изображения; файл скачивается без JavaScript с именем из медиатеки WordPress.
- «О капелле» выводит до шести педагогов в уникальном ручном порядке; детальная страница не показывает пустой блок цитаты и содержит все добавленные фотографии и достижения педагога.
- Блок достижений «О капелле» выводит все опубликованные строки без фильтров, по одной строке на достижение, либо целиком скрывается при отсутствии достижений.
- `/mediagalereya/` выводит навигационный общий блок из трёх последних материалов и две таблицы-preview: до десяти фотоальбомов и до десяти видео с переходом к их полным спискам.
- Полные списки фото и видео отображают все материалы в серверных таблицах с валидным фильтром категории и без пагинации; пустые категории не появляются в фильтрах.
- Фотоальбом не выводится без доступных фотографий; его изображения следуют порядку CMS и открываются в lightbox с серверной ссылкой на оригинал.
- Строка видео открывает внешний видеохостинг в новой вкладке и содержит доступное имя провайдера вместе с его иконкой.
